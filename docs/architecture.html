Factory Inventory Management System

A Vue 3 single-page app on port 3000 calls a FastAPI service on port 8001. The service loads its data from JSON files into memory at startup. There is no database, so every request filters Python lists in memory.

Data flow: changing a filter

  1. The user changes a filter in FilterBar.vue: Time Period, Warehouse, Category or Order Status. Each value is stored in a module-level ref in useFilters.js, so every view shares the same state.
  2. The active view watches those refs and calls getCurrentFilters(). That function maps the Location filter to the warehouse parameter and the Period filter to the month parameter.
  3. api.js builds a URLSearchParams, leaves out any value equal to "all", and sends GET http://localhost:8001/api/….
  4. FastAPI binds the optional query parameters. apply_filters matches warehouse exactly and matches category and status case-insensitively. filter_by_month expands a value like Q3-2025 into its three months and matches each against order_date as a substring.
  5. Pydantic validates the response against the route's response_model, where one is defined. The view stores the JSON in a ref. KPIs, chart series and table rows are computed from that ref and format money with formatCurrency().

Gaps found during investigation

The frontend calls endpoints the backend doesn't have. api.js defines getTasks, createTask, toggleTask, deleteTask, createPurchaseOrder and getPurchaseOrderByBacklogItem. main.py has no /api/tasks or /api/purchase-orders routes, and both return 404 on the running server. App.vue calls getTasks() on load and catches the error.
Inconsistent wiring. Backlog.vue has no route. Reports.vue hardcodes http://localhost:8001 and bypasses api.js.
Hardcoded 2025 dates. The quarter mapping in QUARTER_MAP and the report grouping only cover 2025. Orders from any other year are dropped from the quarterly report.
